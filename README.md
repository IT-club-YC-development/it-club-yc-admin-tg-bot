# OptiBot — MVP scaffold

Минимальный каркас OptiBot: рабочая команда `/start`, структура приложения и согласованные интерфейсы для будущей реализации БД.

## Стек
- Python 3.11+
- aiogram 3
- SQLAlchemy 2 async (контрактный слой пока не привязан к конкретной СУБД)
- `Protocol` + dataclasses для типизированных контрактов

## Запуск
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Добавьте BOT_TOKEN в .env
python bot.py
```

Отправьте боту `/start`.

## Архитектурные правила
1. `handlers/` — Telegram-входы/выходы и валидация формата команды.
2. `services/` — бизнес-правила; handlers не обращаются к SQL/репозиториям напрямую.
3. `database/repositories/` — интерфейсы доступа к данным. Реализации пока намеренно не написаны.
4. Все потенциально I/O-операции асинхронные.
5. Все даты — timezone-aware UTC.
6. Telegram user/chat IDs — `int`; не использовать `username` как идентификатор.
7. В БД хранится запрошенное наказание и его статус отдельно от результата Telegram API. Ошибка применения не должна маркироваться как успешное наказание.
8. Изменение публичного интерфейса согласовывается в PR и одновременно обновляется в `docs/CONTRACTS.md`.

## Что пока не реализовано
- БД и миграции;
- применение наказаний через Telegram API;
- проверка прав, логирование и остальные команды;
- автоматическое истечение наказаний;
- обработка ошибок и тесты интеграции.

Это намеренный scaffold, а не готовый модерационный бот.
